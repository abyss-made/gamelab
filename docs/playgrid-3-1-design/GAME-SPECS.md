# Board, control and feedback specifications

All dimensions below are CSS pixels unless explicitly logical canvas units. The source mockups show one illustrative legal/intended action state per game, not every round phase or final asset production. Use the shared shell from HANDOFF.md, preserve server eligibility and every existing control. The named primary action in games.json is an accessible action summary/alternative, **not an instruction to add another confirmation to existing single-tap moves**.

## A. Draw & Guess · paper and ink

**Composition:** keep the current desktop white 4:3 canvas with narrow adjacent tools and chat rail. Phone: full-width white canvas, status above, horizontal tools and palette below. Brush/eraser/fill are operations; Undo/Clear are history actions. Avoid an unnecessary “Apply brush” button. Private word appears in the drawer’s status, never over the drawing. Guesser sees masked hint + letter count; spectators see only authorized server hints.

**Geometry and surfaces:** logical 800×600 unchanged. Paper `#FFFFFF`, 8px corner; 1px cool-gray edge, no texture/grid that alters player ink. Normal desktop target ~867×650, phone ~364×273. Palette 22 colors at 30px on phone, 44px brush/eraser/fill; selected ring outside the swatch plus aria-pressed. Separate stored brush and eraser sizes remain separate. Size slider displays numeric value and tool name. No new text or redo tool.

**States:** choose screen = exactly six 44px-high word buttons in 2 columns × 3 rows; identify the selection countdown separately from drawing countdown. Guesser choose state shows avatar/name “Nova is choosing…” with no choice payload. Drawing phase has no blocking overlay. Local fill click shows a brief cursor ring, then renders existing flood-fill output; never substitute a whole-canvas tint. Clear asks confirmation without wiping before ack; rejected/rate-limited history action keeps drawing and explains the cooldown. Guesser focus mode retains compact chat; phone tools are absent for non-drawers. Reveal announces the actual word and turn points after the server event. Existing canvas sampling and coalesced pointer flow must remain intact.

## B. Four in a Row · arcade cabinet

**Board:** cobalt frame `#2C55D7`, raised top edge `#6C99FF`, navy recessed slots `#081827`. Keep 7 columns × 6 rows. Desktop disc diameter ~52px inside a 64px pitch; phone pitch ~46–48px, disc ~36px. Scale uniformly; do not round coordinates individually. Red discs `#FF477B`, Yellow `#FFCD2D`; inset ring and textual player identity survive colorblind viewing.

**Interaction:** pointer previews the selected column with an uncommitted translucent disc; touch can use the existing direct column drop, keyboard exposes column buttons with an action label such as “Drop Red in column 4”. Full column is disabled with reason. Accepted drop animates only along its chosen column, using the server’s landing row. A winning line gets a persistent outline on the actual four or more server-specified cells; do not infer a win from animation. Out-of-turn touch says “Nova’s turn” rather than pulsing the wrong player. Preserve winner-stays and rematch logic.

## C. Chess and Checkers · distinct strategy materials

**Shared board:** 8×8, cream `#DFD3BA` and slate `#527080`, subtle edge and a quiet coordinate rail. Mobile board occupies the available square width; controls and move history sit below or in a sheet. Keep the player’s existing orientation. Use original scalable piece silhouettes, not platform-dependent emoji glyphs. Fill contrast must hold on both square colors: ivory pieces `#F8F0DE` with dark edge, navy pieces `#20384D` with light edge.

**Chess:** rook tower crenellations, bishop diagonal slit, queen crown, king cross, pawn head and knight profile are separate reusable SVG symbols. Specimen vectors establish silhouette direction; production needs a complete 12-piece color set at 1×/2×/3×. Selected origin = 2px lime ring; legal empty target = 8px center dot; legal capture = 3px edge ring; last move = subdued filled pair; check = labeled banner plus king ring. These must remain distinguishable at once. Dual clocks show White/Black labels, active border and paused state; use authoritative time and original increment/flag behavior. Promotion is a four-choice keyboard-safe dialog. Keep move history, draw/claim and resign. The sample g1 knight targets f3/h3; render actual legal data in implementation.

**Checkers:** replace glyphs with layered discs: pale timber vs dark slate, concentric inset, king = visible double crown/ring plus accessible “king”. Keep square geometry aligned with Chess but distinct piece depth. Mandatory capture appears in status; selected piece shows only server-legal landing squares. Multi-jump locks the moving piece until that server sequence ends. Captured piece fades only after state confirms the hop. Resign confirmation and logical focus preservation belong to #43; approval of this style does not bypass that work.

## D. Ludo · bright toy, precise play

**Board:** retain the 15×15 cross and all 52 track positions/home lanes. Soften broad colored yards with pale inset wells; use the existing four semantic colors. Tokens are raised discs with stable token numbers 1–4, not anonymous colored spots. Safe cells use a ring/star vector plus accessible “safe”; yard/home positions remain exact.

**Die and actions:** use six original pip layouts in an inset ivory die, 48px phone minimum. Animate cosmetic roll only after receiving the actual value; never generate a substitute value. A six exposes movable token alternatives as ≥44px buttons labeled “Token 2 · 6 steps” below the board. Same selectable token state on board and list. Clicking either emits the same existing intent. Move each accepted token along its actual track, cap travel at 650ms and preserve any earlier server deadline. Show capture, brought-home, no-legal-move and triple-six forfeiture as distinct sentences, not just animation. Timeout messages must retain Phase 2’s once-per-missed-turn accounting.

## E. Pool · tactile table, honest physics

**Table:** proportion follows `g.table`, not the preview SVG’s arbitrary CSS size. Dark rails with quiet grain, teal cloth (`#0A4848` inner, `#175B58` cushion), six black recessed pockets. Ball sprites use numbered faces and solid/stripe patterns at the existing positions/radius. Use device-pixel-ratio rendering (cap as current code), never alter physical radius to make art prettier. Cue ball is clean ivory; 8-ball stays uniquely numbered 8.

**Controls:** adjacent Aim angle and Power rails, each labeled with numeric value; 44px Shoot at the end. Pointer drag aim and fine sliders remain available. Aim guide uses existing collision/first-hit calculation; no added bounce prediction that the engine does not support. Ball-in-hand has a clear placement label, valid/invalid ring and existing confirmation flow. Stage resolving: “Shot in motion…”; suppress submission until the existing busy guard permits it. Foul reason, turn retained/lost, groups assigned and pocketed balls appear in a concise event rail. Animate only authoritative frames, never a new JS/CSS physics simulation. Reduced motion snaps to authoritative final positions and announces shot outcome without altering logic.

## F. Color Stack · original graphic card table

**Cards:** original Playgrid card faces, not UNO trade dress. Reuse existing colors/values: Red, Blue, Green, Yellow, Wild; numbers, Skip, Flip, +2, Wild, +4. Proposed softened face fills `#FF7C83`, `#71B9FA`, `#86D6B3`, `#FFE18A`; dark text with 4.5:1 contrast. Always include the color name and action symbol/label. Desktop private cards ~90×134; phone visible selectable card width ≥48, hand scrolls horizontally **inside its labeled tray**, never the page. Preserve number labels even when fanning; focus brings a card forward without changing selection.

**Table/flow:** draw pile and top discard separated by 20px; current required color is a named badge, especially for Wild. Playable cards get an outline, not full neon fill. A selected legal card may be raised 6px; keep the existing play intent/ack flow, and use the sample “Play Red 5” as a keyboard alternative if needed. Wild opens four named color buttons, Cancel retains hand; no action is sent until the current handler’s requirements are met. Keep & Pass appears only when the rules permit. Penalty draws animate as a short batch while counters always reflect authoritative counts. Opponents’ hands are card backs/counts only. “You are out · spectating” must replace ambiguous waiting copy when #44 is implemented.

## Implementation notes for the SVG mock assets

The static vectors demonstrate composition/materials, not engine truth or final production sprite completeness. Use their colors/edge treatments, then build actual components around existing data. Chess silhouettes need final normalized assets and all piece/size states; Pool needs a complete 16-ball solid/striped sprite family; Ludo needs all token/safe/stacked/home states. These are finite implementation asset tasks, not permission to add stock substitutes or change game geometry. Mock counts, sample names and sentences must be replaced with live values, not copied into production.
