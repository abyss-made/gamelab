## Design direction

**A real tabletop inside a familiar party.** Keep Playgrid navy/lime in the surrounding HUD, controls and selections. Let the game surface carry its own material: white drawing paper, cobalt Four in a Row, parchment/slate strategy boards, four-color Ludo, teal billiards felt, original vivid Color Stack cards. Existing characters remain player identities, not decoration behind legible boards. No new brand, emoji piece sets or external stock illustrations.

The exact palette, typography, spacing and specimen geometry are in `design.css`. Board SVGs are original design references generated by `build.py`, **not production board backgrounds**. Actual board elements must render live state, retain coordinates and have accessible hit targets. No new runtime dependency is required by the direction.

## Layout contract

**Desktop:** 68px HUD; content outer margin 36px; stage + 292px social rail with 24px gap. Pairwise games get a compact two-player strip; multiplayer games use real participant chips or a collapsible roster (the sample's two identities are illustrative, not a limit). Keep timer and current player visible without scrolling; score/chat can collapse in focus mode. Avoid displaying the roster twice in implementation: top strip shows current competitors, rail adds full roster/score context only when useful.

**Phone:** 56px HUD; 12px outer margin; one game column, contextual status, board, local actions, compact Players/Chat launchers. Both drawers are existing party context, not separate rooms. Keep native input visible above the soft keyboard; reserve `env(safe-area-inset-bottom)` for fixed controls. Allow vertical scrolling for unusually large private hands or advanced actions; never hide a primary action behind the review footer. No horizontal page overflow.

**Drawing:** preserve Phase 2's 800×600 logical canvas, ~867×650 normal desktop and ~364×273 normal phone, ~388×291 phone focus. The mockup uses a white vector sketch to show materials; its container is not a mandate to replace the canvas. Desktop tools beside canvas; phone tools under canvas, 44px operations and all 22 swatches at ≥30px. Guesser and spectator layouts omit drawing tools completely and show only authorized hints. The phone drawer specimen moves the private word into the status and removes a redundant bottom “brush” action; brush/undo stay in the toolbar.

**Dense boards:** Chess/Checkers use available full width, roving keyboard focus with coordinates; no two half-sized boards on a phone. Ludo remains 15×15 but gets ≥44px labeled token buttons outside the small cells. Battleship can use ~34–36px cells with aim-then-Fire; provide focus/precision view and keyboard targeting rather than pretending a 10-column board fits 44px cells in 364px. Dots & Boxes retains ≥40px hit areas from Phase 2.

## Interaction and motion contract

| Event | Visual behavior | Timing / authority / reduced motion |
| --- | --- | --- |
| Local hover / focus / selection | Outline, legal-target dots/rings, precise action copy; move focus only on deliberate navigation. | 120ms fade; immediate for keyboard. Reduced motion: immediate. |
| Move submitted | Keep selected origin, show small pending label, disable duplicate action. Do not announce success yet. | Pending until server ack/state. Show reconnect/retry status after 2s; do not auto-resubmit a committed move. |
| Confirmed discrete move | Translate piece between original and destination; retain final-state last-move cue. | 180ms, then release local controls according to server. Reduced: snap, keep cue. |
| Four in a Row drop | Ghost previews chosen column; accepted disc drops vertically and settles once. | 220ms fall + 80ms settle, no bounce loop. Reduced: snap and outline. |
| Ludo roll / travel / capture | Pip die settles to server value; token steps along existing track, capture returns target to yard. | Die ≤280ms; step 65ms, total ≤650ms. Never roll locally or delay deadlines. Reduced: final die/token positions with event sentence. |
| Chess / Checkers | Legal dots vs capture rings vs check banner; one capture removal after confirmed move. | 180ms move, 120ms removal. Multi-jump is server-defined hops, never an invented path. Reduced: snap and last-move cue. |
| Pool / Golf simulation | Render only supplied animation frames/trajectory and final positions. Freeze Shoot while server shot is resolving. | Existing server duration, capped visually only by a separate skip-to-final affordance if supported. Reduced: show final state immediately with a shot summary; never alter physics or skip required state transitions. |
| Card play / draw | Move own selected face to discard after ack; others see card back until authorized. Draw animates from deck to private hand. | 180–240ms; 45ms stagger, total ≤450ms for batch penalties. Reduced: update count and final hand instantly. |
| Answer / vote receipt | “Locked in” or “Answers locked” chip; reveal correctness/authorship only at server reveal. | 120ms receipt, 180ms reveal. Do not reset timer on input selection. |
| Wrong / illegal action | Inline reason next to action, brief border emphasis; keep input and focus. | 160ms outline fade; no shaking/flashing required. Reduced: persistent text. |
| Low clock | Amber below 10s; red + “5 seconds” below 5s; visible numeric value stays. | Once per threshold, never a flashing loop. No sounds if muted; no layout shift. |
| Result | Existing score/result meaning, small bounded confetti only after actual finish, then shared party actions. | Score 240ms; optional confetti ≤700ms once. Reduced: static crown/medal and explicit result. |

No looped attention animation in gameplay. The motion sheet loops solely to demonstrate samples; implementation is event-triggered. Sound remains optional and uses existing settings. CSS animation completion must not dispatch game actions, advance a turn, delay a timeout or decide a win.

## States, permissions and a11y

- Distinguish your turn, opponent turn, simultaneous input, locked/submitted, spectator, out/eliminated, reconnect, empty history, loading and completed. Show **“You are out · spectating”** in Color Stack rather than a false waiting prompt; this is the #44 follow-up, not an already shipped fix.
- Only the server view may supply hand faces, drawing choices, roles, hints and secret words. Do not pre-render secrets and hide them with CSS. No author hints on anonymous Bluff answers. RPS choices remain backs until reveal.
- Confirm Resign in a stable modal with Cancel focused. Preserve it across unrelated state ticks, per pending #43; do not claim a CSS-only fix. Host may End Game; participants may Leave; existing server permissions prevail.
- Timer Off reads **Off**, not 0:00. Do not invent a 3-minute auto-kick rule; #42 needs the owner's decision. Preserve all currently supported settings and Phase 2’s monotonic countdown behavior.
- Persistent keyed DOM, not wholesale board replacement, should preserve logical focus when Claude implements #43. Arrow keys navigate square boards; Enter/Space follows current selection/move protocol. Announce current turn and accepted move via polite live region, not every clock tick.
- Every control gets a name, selected/disabled state and a reason when not usable. Patterns, numbers, initials or suit labels supplement colors. ≥44px phone actions, 24px absolute minimum unless the documented dense-board confirmation alternative applies. Scrolling chat/history is keyboard focusable.
- Loading uses static card/board silhouette with “Connecting to your party…”; no fake countdown or fake live scores. Reconnect keeps board geometry stable, suspends submission and waits for server snapshot. Results keep the party ID, queue, chat and game-specific restart semantics.

## Reproduce this design package

With Python Playwright and Chromium installed, from repository root:

```sh
python3 docs/playgrid-3-1-design/build.py
python3 docs/playgrid-3-1-design/render.py
```

CHROMIUM_PATH may select a system browser. The renderer serves these docs temporarily on loopback; it never starts the game server. It checks all 42 designs for horizontal overflow, image loading and JS page errors, records viewport/content dimensions, and renders three review sheets. It does not claim game functionality or full WCAG conformance. Open index.html through a local HTTP server to inspect sources and motion samples. Asset origins and reuse are in asset-manifest.json.
